# 海战棋规则：双人异步单发版

状态：2026-09-14 用户确认双人异步无时限玩法，并授权使用 Flutter 原生实现。本文件记录规则、实现边界与验收依据。

## 对局目标与舰队

- 两名玩家各有一块独立的 10 × 10 海域，坐标为 A–J、1–10。
- 双方舰队配置相同且公开：五艘船，分别占 5、4、3、3、2 格，共 17 格。
- 两艘 3 格船是独立舰船，分别计算命中与击沉；不能将任意三个相连命中格视作一艘被击沉的船。
- 先击沉对方全部五艘船的玩家获胜。

## 秘密布阵

- 双方可分别布阵，无需同时在线；可手动摆放或随机布阵。
- 每艘船必须横向或纵向连续放置，不能斜放、弯折、重叠或越界。
- 允许不同舰船贴边和对角相邻，不强制留空格。
- 布阵不限时，不自动补齐、不自动准备。
- 玩家放齐全部合法舰船后可确认准备；准备后布阵锁定，不可修改。
- 对手只能获知是否准备，不能看到布阵位置。
- 双方都准备后自动进入战斗，舰船此后不能移动、旋转或修复。

## 轮流攻击

- 首局由服务端随机决定先手；双方同意再来一局时重新布阵，先后手互换。
- 双方轮流行动，每个回合只能攻击对方海域中一个尚未攻击的格子。
- 回合不限时，玩家可随时返回并完成自己的行动。
- 未命中、命中或击沉后均换对方行动；命中不奖励连射。
- 重复攻击、越界攻击、非当前行动方攻击等无效操作不消耗回合、不改变对局。
- 一次有效攻击只生效一次，重试或重复提交不能多打一发。

## 攻击结果与可见信息

- 空格：显示“未命中”。
- 舰船格：显示“命中”；普通命中不公开舰种、朝向或剩余长度。
- 一艘船全部格子被命中：显示“击沉”，公开该舰的舰种、长度和完整位置。
- 舰种只是识别舰船的名称，不附带技能或额外能力。
- 因为允许舰船相邻，击沉后不能将其周围格子自动标为海水。
- 玩家可见自己的完整布阵、对方对自己的攻击记录、自己对敌方的攻击结果及已击沉敌舰。
- 对手未公开的舰船位置由服务端保管，不提前下发客户端。

## 异步继续与离线

- 离开页面、返回大厅、关闭应用、进入后台或断线均不视为认输，不导致跳过回合或自动攻击。
- 没有布阵倒计时、回合倒计时、连续超时判负或离线判负。
- 长期无人操作的对局保持待续，不因闲置自动结束或判胜负。
- 服务端保存布阵、准备状态、攻击记录、舰船损伤、当前行动方及结束结果。
- 玩家重新进入时恢复其有权查看的最新状态，已完成的操作不会因断线撤销或重复执行。
- 异步玩法要求对局进度不依赖任一玩家持续在线；具体存储、入口和通知方案在实现阶段设计。

## 对局结束

- 击沉最后一艘敌舰立即获胜，后手不补射；正常交战没有平局。
- 返回大厅只是离开页面；认输是独立操作，需要玩家明确确认，开战后认输判负。
- 布阵阶段主动取消对局则取消，不计胜负；仅离开页面不取消。
- 战斗中双方同意结束则记为取消，不计胜负；一方提出请求不暂停或终止对局。
- 服务端故障导致对局无法恢复时作废，不计胜负；普通客户端断线不适用此规则。
- 对局结束后展示双方完整布阵，便于复盘。
- 结束结果确定后不再接受攻击或改变胜负；双方同意“再来一局”才创建新对局。

## 首版范围与规则验收

首版只有上述固定规则，不加入齐射、雷达、范围轰炸、移动、修复或命中连射。

后续实现至少应证明：

- 合法布阵边界与非法布阵拒绝；贴边和对角相邻合法。
- 准备后锁定，双方准备后开始，双方无需同时在线。
- 单发交替、命中后换人、独立舰船击沉判断及最后一击立即结束。
- 普通命中不泄露舰种，击沉只揭示对应舰船，不推断周围为空。
- 非行动方、重复请求、无效坐标不能改变状态或多次消耗回合。
- 离开、断线和长期闲置均保留进度，恢复后继续原回合。
- 取消、认输、双方同意结束及再来一局符合上述结果与先后手规则。
- 客户端收不到对手尚未公开的布阵数据。

规则参考：[Hasbro Battleship 官方介绍](https://instructions.hasbro.com/en-us/instruction/Battleship-Classic-Board-Game-Strategy-Game)。异步无时限、信息公开和退出处理以本文件确认的项目规则为准。

## 实现选型与接入声明

2026-09-14 用户授权使用 Flutter 原生实现。`gameId` 为 `battleship`，显示名为“海战棋”，默认 Android 竖屏，采用 Core Contract 与 Lightweight Board 的交互约定。棋盘使用 Flutter CustomPainter，布阵、选格、确认开火、菜单与结算使用 Material 3 控件；沿用 design system 1.0.0 的语义颜色、字体和间距。海域使用 surfaceContainerLow，舰船使用 secondaryContainer，选中位置使用 primary，命中用 ×、未命中用圆点、击沉用舰船边框。公开按钮遵守 48dp，密集棋盘整格命中，开火需要独立确认。没有另加 SHOULD 偏离。

本游戏通过鉴权 HTTP 接口和独立 SQLite 持久化表实现异步对局，复用现有账号和 API 客户端，不创建 Godot Activity、launch ticket、实时对局槽位或闲置清理记录。双方无需同时在线，可从海战棋对局列表进入或继续；可与离线玩家创建对局。单个账号可以保留多个异步对局，对局列表支持分页。客户端只获得参与者视角。

手动点击棋盘保存选定舰船的位置，可重新选择船和横竖方向调整；随机布阵也先保存，完整布阵后单独确认准备。客户端使用持久化操作编号处理未确认请求，恢复后重试相同请求，服务端通过 SQLite 事务和操作账本实现幂等。轮流攻击采用“选格、确认开火”，网络确认前不将选择显示为命中。对局页面前台定期同步、后台停止同步，恢复时先获取服务端状态再允许操作；网络请求超时不是游戏回合超时。

UI 验收状态：空对局列表、选对手、空布阵、手动/随机布阵、非法放置、准备等待、自己的回合、对手回合、选格、发送中、命中/未命中/击沉、我的海域、网络失败与重试、后台恢复、认输/取消确认、双方同意结束、胜负、完整布阵揭示、再来一局以及可见返回与系统返回。浅色与深色、窄手机与常见手机宽度均检查。
