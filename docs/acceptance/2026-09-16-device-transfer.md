# 设备迁移验收

## 范围与要求复核

范围：Flutter 账号入口/迁移页面、本地收藏恢复、Go 账号会话、对局连接撤销、管理员恢复命令。采用项目 Material 3 Core Contract，保持既有主题与导航，不引入新顶层目的地。

基线：[已批准 F3 设计](../specs/2026-09-16-device-transfer.md)。实现后重新对照完整方案与 diff，检查生成/过期/失败/重试/成功、旧会话退出、收藏先恢复再同步、后台重启和返回行为。

- MUST：每设备单次兑换，服务端权威切换；普通迁移保留完整 v3 收藏存档；本地恢复失败不发布登录；HTTP 和对局事务在迁移之后拒绝旧会话。对应自动化测试已通过。
- 复核修复：对局启动生成新恢复凭据会删除旧恢复 token，因此活动连接不能用 token 是否仍存在判定迁移；改为连接携带账号世代并在动作事务内核验，既保留正常重连语义，又拒绝迁移后的旧动作。
- 复核修复：HTTP 认证和后续写入之间可能发生迁移；增加事务级身份核验，避免旧收藏请求覆盖新设备数据。
- SHOULD：主页面只保留迁移码输入与直接后果；管理员恢复限制放在主动帮助弹层。旧设备页面保留复制码和有效性说明。
- MAY：使用 8 位 Base32 码与同一恢复入口；首版不加相机权限、二维码或账号合并。

## 自动化证据

- Go auth：生成不退出、过期边界、替换、取消、并发兑换单赢家、同 receiver 延迟重试、新访问凭据有效、旧 access/refresh 失效、恢复码与限流、事务失败回滚。
- Go HTTP + 实际 WebSocket：迁移后旧连接关闭、恢复 token 失效，新设备保留同一账号和活跃五子棋对局；日志无迁移凭据。
- Flutter：断网后重建控制器沿用 receiver、恢复存档和清除迁移日志后才发布登录、本地写入失败可重试、重复提交阻止、输入错误保留。
- `bash tool/verify.sh`：通过；追加 Go 日期兼容检查、Flutter 过期状态及重建 SessionController 的重试测试也通过。

## Android 运行时（初次验收）

使用隔离 worktree 服务、测试账号、独立 `me.zqydev.gamebox.debug` 包名，遵守共享 Android exclusive lease。隐私构建掩蔽迁移码与输入内容；截图临时检查，不提交或发布。

实际运行 Android API 36 两台模拟器，连接隔离的真实 Go 服务：

1. 从注册页进入原账号，真实完成两次抽卡，保存 1 张收藏；旧设备从大厅生成迁移码，新设备从「已有账号」迁入，旧设备自动回到注册页并说明账号已迁移。
2. 新设备收藏进度为 1/48；通过 Dart VM 只读检查，数量数组、serial=2、claimed、winning 与旧设备迁移快照逐项相同；生产同步层 `_sent` 总量为 1，HTTP 收藏查询也为 1。新设备进程重启后登录与抽卡状态保持。
3. 使用生产 `gameboxctl recovery create` 命令签发恢复码；暂停本地服务制造真实 HTTP 超时，确认 pending 与错误/重试状态，强制关闭 App，再恢复服务并打开 App，自动完成迁入，旧设备退出。恢复后的收藏为 1/48，抽卡进度按管理员恢复边界重新开始。
4. 捕获并检查生成码、明/暗迁入页面、键盘、无效码、帮助弹层、pending、网络失败、迁移成功大厅、旧设备退出、普通与管理员恢复后的收藏界面。布局、换行、主操作、安全区均无阻塞 UX 问题；测试凭据通过隐私构建掩蔽。
5. 模拟器曾出现覆盖安装空间不足；明确识别到设备仍运行旧测试包后，仅卸载本任务独立 debug 包并安装当前版本，重跑管理员恢复与中断重启场景通过，未清空原 Gamebox 包数据。

以上为本地真实服务与 Android 模拟器证据，不代表生产部署或物理手机验收。活跃对局迁移与 WebSocket 撤销由真实 Go HTTP/WebSocket 集成测试证明，未将其描述为双模拟器完成整局游戏。

最终检查通过：最新版 APK 能将管理员恢复后的账号再次迁入另一台设备；页面返回按钮及 Android 系统返回均成功取消未用迁移码并返回大厅，截图已检查。完整 `tool/verify.sh` 最终复跑通过。

验收结论：本次实现范围完成，上述自动化与 Android 运行时验收通过。
