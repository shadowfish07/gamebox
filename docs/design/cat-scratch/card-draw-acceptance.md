# 抽卡 UX 验收

范围与 Profile：Core Contract；按 [用户批准的连续抽卡设计](../../specs/2026-09-07-card-draw-design.md) 实现。旧刮奖规则退出当前验收基线。

MUST：每抽必得、四档层次、一次点击继续、有限预接队列、停止点击不自动抽取、可靠保存和旧存档迁移。
SHOULD：公共控件沿用 token，奖品与操作可读；无新增偏离。
MAY：六张最近获得、系统 click 与分级触感。

## Android UX 检查

首轮运行发现静止卡背被镜像、入场时透视位移侵入下方状态行，已修正静止朝向、减小透视深度和入场位移，并为卡面保留运动空间。小屏错误横幅出现后也曾挤压 NEW/稀有度行，已使用弹性文本约束修正，并在四档小屏保存失败场景补测。

最终在 slot 0 租约内运行生产 `ScratchPage`、`ScratchController`、`CardDrawFlow` 和绘制组件，临时检查入口只注入可控抽签随机源及独立文件存储。检查 Android API 36 深色 412×891 与浅色 360×640 的初始卡背、四档翻面中间帧/结束态、NEW、重复数量、最近获得和错误重试。真实点击主按钮验证一击即抽；八次快速输入最多预接一张；停止输入后无额外抽取；HOME/返回后清空预接且已保存数量不变；保存失败重试未重复发卡。最终截图无镜像、控制区遮挡或溢出，当前应用进程日志未出现布局溢出/未处理异常。

十连入口、自动抽取和汇总页均不在最终实现中。检查使用实际生产 UI，非 mock UI；声音与触感的真机感受、真实 GPU 性能不由模拟器证明。本次没有修改网络协议或云端权威，因此未跑双设备网络 E2E。截图、定向入口和日志均保留在忽略目录，不进入固定 gate 或提交。检查完恢复设备尺寸/密度和正式入口 APK，移除检查端口并释放租约。
