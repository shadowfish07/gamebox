# Gamebox 收藏卡片内容

先读 [内容标准](references/content-standard.md)，再依据当前任务创作或改写。
该参考文件是本项目故事规则的唯一正文；`docs/design/collection-content-standard.md` 是发现入口。

## 读取项目事实

- 从仓库根目录读取 `app/lib/features/scratch/scratch_catalog.dart`，核对本次涉及的角色与系列。
  查看 `imageAsset` 指向的原画，而非凭职业名猜测服饰和道具。
- 读取本次对应的系列说明与明确的用户要求；现有代码决定当前字段和实际展示入口。
  不把旧设计文档中的奖池大小、抽取方式或样稿采用状态当成当前事实。
- 保留既有编号、名字、职业、稀有度、美术映射与已明确的角色事实。仅在用户授权的范围内改动。

## 写作与批量复核

根据标准规划每张卡的人物核心、事件和画面呼应，再写正文。
普通写可记住的生活细节，稀有写有结果的小事件，史诗写来历与选择，传说写可独立阅读的完整篇章。

字数是编辑目标，不是质量证明。先检查动机、动作、结果和角色辨识度，再统计正文有效字符与段落。
同职业的猫狗要有不同处境与解决办法；整批检查重复情节、套话、跨卡关系和过度集中的奇幻意象。

改写既有卡时比较改动前后的稳定字段，确保只是获授权的内容变化。
交付逐卡内容及简短编辑记录，说明字数、人物核心、画面呼应和例外理由；记录不进入玩家正文。

## 应用与验证

用户要求应用时，写入当前生产目录，不停在样稿或另建一份未被应用使用的目录。
只讨论或生成草稿时，清楚标识采用状态。正文保持纯文本，以空行分段，不新增无需要的数据字段。

实际换上长故事后，遵守仓库测试与 UI 验收规则，在真实生产详情页检查最长文本的换行、滚动、
关闭和下方操作区域。文案统计、Widget 测试或静态排版不能替代截图检查。
本 Skill 不要求额外审批，不授权部署、推送或修改概率/存档；这些继续服从当前用户任务和项目规则。
